# WaresWood

Сайт-витрина изделий из массива дерева: каталог, карточки товаров и заявки в Telegram.
Чистый PHP без фреймворка и Composer — таковы ограничения shared-хостинга.

## Структура

```
front/            → public_html/front/     (деплоится джобой frontend-deploy)
  index.php                                главная с каталогом
  product.php                              карточка товара
  products.php                             слой совместимости: модель → массив $products
  admin/                                   админка каталога
  src/                                     код приложения (модели, сервисы, репозиторий)
  css/ js/ images/                         статика витрины
deploy/           → public_html/           (деплоится джобой backend-deploy)
  send.php                                 отправка заявок в Telegram
data/             только на сервере        каталог, конфигурация админки, счётчики
uploads/products/ только на сервере        фотографии, загруженные через админку
```

`send.php`, `config.php` и `getUpdates.php` в корне репозитория — рабочие копии для
локальной разработки, на сервер они не попадают: деплоится только содержимое `deploy/`.

## Деплой

GitHub Actions, workflow `.github/workflows/deploy.yml`, триггер — push в `main`.
Два параллельных джоба заливают файлы по FTP: `front/` в `public_html/front/`,
`deploy/` в `public_html/`. Нужны секреты `FTP_HOST`, `FTP_USERNAME`, `FTP_PASSWORD`.

Флаг `dangerously-ignore-sync: true` отключает файл состояния синхронизации: каждый
запуск перезаливает все файлы и никогда ничего не удаляет с сервера. Отсюда главное
архитектурное следствие — **данные каталога нельзя хранить внутри `front/` или
`deploy/`**, иначе следующий деплой затрёт правки из админки. Поэтому `data/` и
`uploads/` лежат рядом с ними, не входят в git и создаются приложением сами.

Корневой `.htaccess` тоже не деплоится (`deploy/.htaccess` в `.gitignore`) и
поддерживается на сервере вручную.

## Админка каталога

Адрес: `/front/admin/`. Требования: PHP 8.1+, расширения `mbstring` и `fileinfo`;
`gd` не обязательно, но с ним загруженные фотографии перекодируются и уменьшаются.

### Первый запуск

1. Задеплойте `main` и откройте `/front/admin/`. Появится помощник настройки.
2. Введите логин и пароль (не короче 12 символов) — помощник покажет готовое
   содержимое файла конфигурации.
3. Создайте по FTP файл `public_html/data/admin.config.php` с этим содержимым.
   Файл создаётся вручную намеренно: иначе в промежутке между деплоем и первым
   входом пароль администратора мог бы задать кто угодно.
4. Обновите страницу и войдите.

Каталог начинается пустым: сначала создайте категорию, затем добавляйте в неё товары.

### Что умеет

Категории — создание, переименование, изменение порядка, удаление вместе с товарами.
Товары — создание, редактирование названия, описания, цены и единицы измерения,
перенос между категориями без изменения ссылки, изменение порядка, удаление.
Фотографии — загрузка сразу нескольких файлов (JPEG, PNG, WebP до 8 МБ), выбор
главной, удаление. Первая фотография показывается в каталоге и в списке товаров.

### Хранение

Каталог — `data/products.json`, запись атомарная (временный файл плюс `rename`) и
сериализованная через `flock`, поэтому одновременные правки не портят файл.
Фотографии — `uploads/products/` со случайными именами; при доступной GD
изображения перекодируются, что снимает EXIF и отсекает файлы-полиглоты.

### Красивый URL /admin

Сейчас админка живёт по `/front/admin/`, чтобы не трогать серверный `.htaccess`.
Для `/admin` добавьте в `public_html/.htaccess`:

```apache
RewriteRule ^admin/?$ front/admin/index.php [L]
```

## Локальный запуск

```bash
php -S 127.0.0.1:8000 -t .
```

Корень репозитория играет роль `public_html`, поэтому витрина открывается по
`http://127.0.0.1:8000/front/index.php`, админка — по `/front/admin/`.
Каталоги `data/` и `uploads/` создадутся автоматически при первой записи.
